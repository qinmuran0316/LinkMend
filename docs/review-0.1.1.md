# LinkMend 0.1.1 代码与功能检查

日期：2026-10-22。检查版本：0.1.0；修复版本：0.1.1。

## 检查结果

重点覆盖扫描、诊断、候选确认、ShellLink 读写、备份、撤销、历史展示、窗口退出和发布脚本。原有 56 项测试通过；补充回归测试后复现了 12 个失败场景，随后完成修复。

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| 撤销异常时无条件回滚 | 尚未写入就检测到文件变化时，异常处理仍可能覆盖用户新内容或重建已删除文件 | 记录实际写入阶段；只回滚本次写入且仍匹配的内容，提交前再次校验 |
| 备份后未再校验整批文件 | 后一项发生变化时，前面的文件可能已经被恢复 | 撤销备份完成后，在首个恢复动作前重新检查所有剩余文件 |
| 原始快照逐项读取 | 后一项快照丢失或损坏时，前面的项已被修改 | 预检所有快照的存在性与哈希，使用已校验的快照字节 |
| 一项恢复即视为整批撤销 | 部分撤销后无法继续处理剩余项目 | 按路径和前后哈希逐项匹配恢复记录，界面显示剩余数量 |
| 扫描先读取后计算哈希 | 快捷方式在读取期间变化，旧诊断可能绑定到新文件哈希 | 比较读取前后哈希，变化时不生成修复计划 |
| 枚举阶段不响应取消 | 大目录收集期间取消不起作用 | 在根目录、文件枚举与显式文件收集阶段检查取消令牌 |
| 历史结构和身份校验不足 | 空条目导致历史界面异常，批次号与文件名不一致仍被加载 | 验证结构、操作、状态、路径、哈希和批次身份，忽略损坏记录 |
| 快照名与重解析点限制不足 | 特殊目录名、NTFS 数据流或重解析点进入快照读取流程 | 限制快照命名格式，拒绝重解析点目录和文件，读取时验证哈希 |
| 写入层缺少提交前校验 | 修复预检后原快捷方式再次变化时，临时文件仍可能覆盖它 | 将预期哈希传入写入层，加载前及提交前重新检查 |
| 替换失败回退到移动覆盖 | 可能绕过替换失败原因，削弱文件元数据保护 | 保留原子替换错误，停止操作并保留原文件 |
| 根目录为重解析点时仍遍历 | 与“不跟随重解析点”的扫描和搜索约定不一致 | 检查遍历根目录，显式快捷方式也排除重解析点 |
| 部分安全边界只由界面保证 | 重复计划、多余候选或缺少哈希时的状态不一致 | 核心层拒绝重复项和手动诊断项的候选改写，统一可修复条件 |
| 写入期间可关闭窗口 | 后台线程随进程退出，修复或撤销可能中断 | 文件写入期间阻止关闭，扫描仍可取消退出 |
| 使用旧界面缓存撤销 | 历史已删除或损坏后仍可继续使用缓存记录 | 撤销前必须重新加载有效记录 |
| 资源管理器使用相对程序名 | 打开文件夹时可能受到同目录同名程序影响 | 指定系统 Windows 目录中的 explorer.exe |
| 发布参数未经限制参与清理路径 | 错误运行时参数可能改变清理目录 | 限制配置和 Windows 运行时参数，验证绝对清理路径范围 |
| 应用项目重复定义版本号 | 发布包版本和应用版本可能不同步 | 统一读取 Directory.Build.props 的 0.1.1 |

## 验证

- Release 构建启用 `-warnaserror`，结果为零警告、零错误。
- 82 项自动化测试通过，包含真实 `IShellLink` / `WScript.Shell` 扫描、修复、参数保留及字节级撤销，以及历史界面和写入期间关闭保护。
- 故障测试覆盖预检后修改和删除、损坏和丢失快照、部分撤销重试、写入后外部修改、无效历史、重复计划和只读文件。
- NuGet 已知漏洞审计包含传递依赖，未报告已知漏洞；该结果不等同于不存在未知漏洞。
- 发布脚本已生成 `artifacts/release/LinkMend-v0.1.1-win-x64.zip`；包内 EXE 与发布目录 EXE 的 SHA-256 一致，实际启动显示 v0.1.1，扫描按钮就绪并以退出码 0 正常关闭。
- 路径穿越形式的运行时参数已在参数绑定阶段被拒绝，没有进入发布或文件清理操作。
- 本地测试报告与依赖审计结果位于 `artifacts/test-results/`。

## 边界

- 文件哈希属于乐观并发检查，最后一次检查与系统替换调用之间仍存在很短的跨进程竞争窗口，不提供对恶意进程的独占隔离。
- 批次预检保证在已发现冲突时不启动恢复；恢复开始后出现新的 I/O 错误或冲突，仍可能部分完成。剩余条目可以重试。
- 本地备份仍是明文快照和 JSON，哈希用于发现内容变化，不提供抵抗同权限进程篡改的身份认证。
- 不支持原子替换或无法保留元数据的文件系统会报告失败，保留原文件及备份。
